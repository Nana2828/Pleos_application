# 주행 계산 코드 (drive-core)

> **한 줄 요약:** 주행 기록·효율·코스 판정·데이터 규격 읽고 쓰기를 화면과 떼어 낸 순수 Kotlin 코드입니다. PC에서 시험 67개가 모두 통과합니다. 팀 앱 `app/`이 생기면 `core` 패키지로 그대로 옮깁니다.

- 작성 2026-11-08 · D · 💡 제안 단계입니다. 팀 앱 구조(`docs/app-structure-proposal-D.md`)가 회의에서 정해지면 옮깁니다.
- 안드로이드 API를 쓰지 않습니다. 그래서 에뮬레이터 없이 PC에서 바로 시험합니다.

## 코스 판정은 이렇게 합니다

1. **진입:** 출발점 50m 안에 들어온 뒤, 코스 방향으로 30m 이상 나아가면 진입입니다. 출발점 쪽으로 거꾸로 오는 차나 반대 방향으로 도는 차는 진입으로 보지 않습니다.
2. **완주:** 도착점 50m 안에 들어오고 **코스의 80% 이상을 지나왔을 때** 완주입니다. 출발점과 도착점이 같은 고리 코스에서 출발 직후를 완주로 착각하지 않게 하는 조건입니다.
3. **일치율 (규격 ③ `on_course_ratio`):** 진입부터 완주까지의 위치 중 코스 폭(`corridor_m`) 안에 있던 비율입니다. **진입 전 위치(출발점까지 오는 길)는 넣지 않았습니다.** 코스를 고른 뒤 출발점까지 가는 길은 코스 주행이 아니기 때문입니다.
4. **커버리지 (새로 더함):** 코스 선을 10m 간격으로 나눠, 실제로 지나간 부분의 비율입니다. 지름길로 도착점에 가면 완주는 되지만 커버리지가 낮게 나옵니다(시험: 대각선 지름길 → 커버리지 0.3 미만).

## 옛 코드와 달라진 점

- 신호에 누적거리·배터리·연료·차 연비/전비를 더했습니다(규격 ② 버전 2). 주행 세션이 시작·끝 순간의 값을 기록해 효율 계산에 씁니다.
- 효율에 "출처 고르기"를 더했습니다. 차가 준 값 → 전후 차이 계산 → 없음 순서입니다.
- 재생 파일에서 모르는 신호 종류는 멈추지 않고 건너뛰고 개수를 셉니다(옛 코드는 오류). 버전 1 파일도 읽습니다.
- JSON 라이브러리를 안드로이드의 `org.json`에서 `kotlinx.serialization`으로 바꿨습니다. PC에서 시험하기 위해서입니다.
- 코스 진입·완주·커버리지 판정은 새로 썼습니다. 옛 시험 앱에는 "그린 모양과 내비 경로 겹침"만 있었습니다.

## `app/`으로 옮길 때 할 일

1. 패키지 이름을 바꿉니다(`ai.pleosapp.core` → 앱 패키지 아래 `core`).
2. `kotlinx-serialization-json` 의존성을 `app/build.gradle.kts`에 더합니다.
3. 시험 파일과 `src/test/resources/`를 `app/src/test/`로 옮깁니다.
4. 차량 신호 소스(Vehicle SDK·위치)와 재생 소스가 `DriveSignalSource`를 구현하게 합니다.

## ⬜ 합의 필요

- **패키지 이름:** 앱 이름이 정해지지 않아 `ai.pleosapp.core`를 임시로 썼습니다.
- **결과의 시작·끝 시각:** 규격 ③은 `started_at`을 "코스 첫 진입"으로 적었습니다. 지금 코드는 주행 기록(기어 D~P)의 시각을 씁니다. 앱이 코스 진입 때 기록을 시작할지, D~P 전체를 기록하고 코스 부분만 결과로 낼지 정해야 합니다.
- **커버리지를 규격 ③에 넣을지:** 지름길을 거르려면 필요합니다. 넣는다면 이름(예: `course_coverage_ratio`)을 C·E와 정합니다.
- **효율을 못 구했을 때:** 지금은 값과 출처를 모두 `null`로 보냅니다. 화면 표시는 E와 정합니다.
- > ⚠️ 확인 필요: Vehicle SDK의 연비·전비 값이 "이번 주행 평균"인지 "순간 값"인지 문서로 확인하지 못했습니다.
