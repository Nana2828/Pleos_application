> 최신 안정성 점검: [문제·수정 내용과 검증 범위](#안정성-점검-상세--2026-11-09)를 먼저 참고하세요.

## 차량 앱 담당자용 QR 연동 안내

차량 앱은 **Android Automotive / Kotlin, Pleos Connect 환경**이며 다른 팀원이 담당합니다. 이 저장소는 스마트폰 웹 프로젝트입니다. 이 절은 차량 팀에 전달하는 참고 안내이며, 차량 앱 코드는 이 웹 저장소에서 수정하지 않습니다. 아래 Kotlin 코드는 담당자에게 전달할 URL 생성 예시이고 차량 프로젝트에 적용하거나 컴파일한 코드는 아닙니다.

### 전체 흐름과 역할

1. 차량 앱에서 주행이 완료되면 결과를 서버에 저장합니다. 저장 요청 주소와 방식은 서버 팀과 별도로 확정합니다.
2. 서버가 저장한 기록의 `tripId`를 차량 앱에 반환합니다. 테스트에서는 이 단계 대신 `abc123`을 사용합니다.
3. 차량 앱은 웹 기본 주소에 `?tripId=...`를 붙여 **전체 URL 문자열**을 만듭니다.
4. 차량 앱 담당자가 이 문자열을 QR 생성 라이브러리에 전달해 결과 화면에 표시합니다. QR 라이브러리와 Pleos 화면에 표시하는 방법은 차량 앱 팀에서 선택·구현합니다.
5. 사용자가 휴대폰 카메라로 QR을 읽어 URL을 열면 웹이 `tripId`를 읽고 해당 결과와 GPS 경로를 표시합니다.

QR에는 `abc123`만 넣거나 API 주소를 넣지 않고 **사용자가 열 스마트폰 웹 URL**을 넣습니다. 현재 웹 내부에 카메라 스캐너나 QR 이미지 생성 기능은 없습니다.

### QR에 넣을 URL 규격

```text
{배포된_웹_기본_URL}?tripId={URL로_인코딩한_주행_ID}
```

| 구분 | 예시 | 사용 조건 |
| --- | --- | --- |
| 현재 개발용 | `http://192.168.203.63:5173/?tripId=abc123` | 개발 PC 서버 실행, 휴대폰과 PC가 같은 Wi-Fi에 연결되어야 합니다. |
| 실제 서비스용 형태 | `https://drive-run.example.com/?tripId=abc123` | 설명용 가상 도메인입니다. 실제 배포된 웹 주소로 교체해야 합니다. |

`192.168.203.63`는 PC의 사설 IP이며 개발용입니다. IP 변경, 다른 Wi-Fi, 외부 이동통신망에서는 이 주소를 그대로 사용할 수 없습니다. 운영 QR에 개발 IP나 `localhost`, `0.0.0.0`을 넣지 마세요. 운영에서는 **실제 배포된 HTTPS 웹 기본 주소**를 사용합니다. 웹이 하위 경로에 배포된다면 그 경로까지 기본 주소에 포함합니다.

현재 ID는 대소문자를 구분하며 영문·숫자·밑줄·하이픈 1~64자를 허용합니다. `tripId`는 한 번만 전달하고, 초기 결과 화면용 QR에는 `#ranking`을 붙이지 않습니다. 서버 ID 규격이 달라지면 웹 검증 규칙과 함께 조정합니다.

### Kotlin에서 URL 만들기 — 참고용

아래 함수는 **QR 이미지가 아니라 QR에 넣을 URL 문자열**을 만듭니다. Android의 `Uri.Builder.appendQueryParameter()`가 이름과 값을 인코딩하므로 `tripId`를 미리 인코딩해서 전달하지 않습니다. [Android 공식 Uri.Builder 문서](https://developer.android.com/reference/android/net/Uri.Builder#appendQueryParameter(java.lang.String,java.lang.String))를 참고하세요.

```kotlin
import android.net.Uri

fun buildTripResultUrl(webBaseUrl: String, tripId: String): String {
    require(Regex("^[A-Za-z0-9_-]{1,64}$").matches(tripId)) {
        "주행 ID 형식을 확인해 주세요."
    }
    val base = Uri.parse(webBaseUrl)
    require(base.scheme in listOf("http", "https") && !base.host.isNullOrBlank()) {
        "웹 기본 URL을 확인해 주세요."
    }
    require(base.query == null && base.fragment == null) {
        "기본 URL에는 쿼리와 #fragment를 넣지 마세요."
    }
    return base.buildUpon()
        .appendQueryParameter("tripId", tripId)
        .build()
        .toString()
}

// 테스트용. 운영에서는 설정 값을 실제 배포된 HTTPS 웹 주소로 바꿉니다.
val webBaseUrl = "http://192.168.203.63:5173/"
val tripId = "abc123" // 실제 연동에서는 저장 성공 응답의 tripId 사용
val qrContent = buildTripResultUrl(webBaseUrl, tripId)
// qrContent: http://192.168.203.63:5173/?tripId=abc123
// 이 문자열을 차량 앱의 QR 생성기에 전달하고 결과 화면에 표시합니다.
```

차량 앱에서는 기본 URL을 한 곳의 환경 설정으로 관리하면 개발/운영 전환 시 주소만 교체할 수 있습니다. 저장 실패나 `tripId` 누락 시에는 운영에서 `abc123`으로 대체하지 말고 저장 오류를 안내합니다. 다음 주행 완료 시에는 이전 주행 ID가 남지 않도록 새 저장 응답의 ID로 QR을 갱신합니다.

### 실제 서버 연결 시 합의할 내용

| 항목 | 차량·서버·웹 담당자 간 합의 내용 |
| --- | --- |
| ID 발급/저장 | 서버가 주행 결과 저장 성공 후 고유 ID를 반환하는 방식, 저장 실패/재시도 처리 |
| 결과 조회 API | 조회 주소, 요청 인증, 응답 JSON, 없는 기록/접근 불가/만료의 오류 형식 |
| QR 웹 주소/공유 권한 | 실제 배포 웹 URL, 로그인 또는 공유 허용 범위, 유효 기간 및 서버의 권한 검사 |

저장 성공 응답은 예를 들어 `{ "tripId": "abc123" }`처럼 합의할 수 있지만 **현재 확정된 서버 규격은 아닙니다**. 차량 앱은 서버에서 받은 ID를 QR URL에 사용하고, 웹은 같은 ID로 결과를 조회합니다. 결과 응답 필드는 아래 **FastAPI 연동 구조**와 **QR URL로 샘플 주행 기록 3개 조회하기** 절에 정리되어 있습니다.

현재 `getTripById(tripId)`는 **로컬 샘플 3개만** 조회합니다. 서버가 발급한 실제 ID는 아직 조회되지 않습니다. 실제 연동 시 웹 담당자가 `app.js`의 이 함수 내부를 확정된 API 호출로 바꿔야 합니다. URL 형식과 `loadTripFromUrl()` → `renderTrip()` → 지도 표시 흐름은 유지할 수 있습니다. ID를 안다는 것만으로 조회 권한이 보장되지는 않으며, 실제 권한 판단은 서버에서 수행합니다.

### 팀 간 테스트 순서와 현재 검증 범위

1. 개발 PC에서 `node server.cjs`를 실행하고 휴대폰을 같은 Wi-Fi에 연결합니다.
2. 휴대폰에서 `http://192.168.203.63:5173/?tripId=abc123`을 먼저 직접 열어 확인합니다. PC IP가 바뀌면 현재 주소로 바꿉니다.
3. 차량 앱 팀이 같은 URL로 테스트 QR을 생성합니다. 휴대폰 카메라로 QR을 읽고 `abc123`의 코스·날짜 옆 ID·기록이 맞는지 확인합니다.
4. `def456`, `ghi789`도 같은 방법으로 시험합니다. `tripId=missing`에서는 다른 기록이 아닌 오류 안내가 나와야 합니다.
5. 운영 연결 시 웹 기본 주소를 실제 배포 URL로 바꾸고, 웹의 조회 함수를 실제 API에 연결한 뒤 서버 저장 → 반환 ID → 차량 QR → 휴대폰 결과를 함께 확인합니다.

위 Kotlin 예시의 차량 빌드, Pleos Connect 결과 화면, 실제 QR 인식, 서버 저장·조회·공유 권한은 이번 문서 작업에서 검증하지 않았습니다. 웹의 기존 코드와 샘플 조회 기능은 그대로 유지합니다.

## 실행 및 휴대폰 접속

Node.js가 설치된 PC에서 프로젝트 폴더를 열고 실행합니다. 별도 npm 설치나 빌드는 필요 없습니다.

```powershell
node server.cjs
```

- PC: http://localhost:5173/
- 같은 Wi-Fi의 휴대폰: 터미널에 출력된 **Wi-Fi 주소**로 접속합니다. 설정 당시 주소는 http://192.168.203.63:5173/ 입니다. PC IP가 바뀌면 새 주소를 사용하세요.
- 랭킹 바로 열기: 주소 끝에 `#ranking`을 붙입니다.
- 종료: 실행 터미널에서 `Ctrl+C`를 누릅니다.

서버는 `0.0.0.0:5173`에서 접속을 받습니다. `0.0.0.0`은 수신 설정이며 휴대폰 주소창에는 PC의 Wi-Fi IP를 입력해야 합니다. 휴대폰에서 localhost는 휴대폰 자신을 가리킵니다.

접속이 안 되면 같은 Wi-Fi인지, 게스트 Wi-Fi의 기기 간 통신 제한이 있는지 확인하세요. Windows 방화벽 허용 창이 나타나면 신뢰하는 개인 네트워크에서 Node.js를 허용하세요. 이 프로젝트는 방화벽이나 공유기 규칙을 자동 변경하지 않습니다.

## 현재 화면과 사용 방법

두 페이지 사이의 전환은 하단 **내 기록 / 친구 랭킹** 메뉴로 통일했습니다. 비교 버튼, 랭킹의 뒤로 버튼, 최근 주행 카드는 제거했습니다.

### 내 기록

- 화면 높이에 맞춰 실제 지도 높이가 변합니다. 경로 전체 자동 맞춤, 이동, 확대·축소는 유지됩니다.
- 거리 `42.3 KM`를 큰 핵심 숫자로 표시하고 시간 `1:24:10`, 연비 `12.8 KM/L`, 지역 `수원시`는 아래의 3열 보조 지표로 표시합니다.
- 데모 문구, 조작 안내, 지도 출처를 유지합니다. 요약 수치는 데모 좌표로 계산한 값이 아닙니다.

### 친구 랭킹

- **나의 종합 순위 3위**와 2위–1위–3위 미니 시상대를 표시합니다. 기존 닉네임과 아바타를 사용하고 본인은 라임 테두리로 구분합니다. 데모 순위이며 산정 기준이 미확정임을 명시합니다.
- **평균 연비 / 누적 주행시간 / 누적 주행거리** 탭을 누르면 선택 부문의 전체 친구 순위를 표시합니다.
- 선택한 탭과 내 행은 라임 배경·검은 글씨로 구분합니다.
- 샘플 데이터에서 내 순위는 **연비 2위, 시간 3위, 거리 3위**입니다. 입력된 배열 순서를 그대로 표시하며 재정렬하거나 순위를 새로 계산하지 않습니다.
- 목록 위에 내 순위와 기록이 항상 표시됩니다. **내 순위 보기**를 누르면 목록 안에서 내 행으로 이동하고 포커스를 줍니다.
- 친구가 많으면 목록 안에서만 스크롤됩니다. 탭과 내 순위 요약은 목록 밖에 남습니다.
- 내 데이터가 없는 부문은 찾기 버튼이 비활성화됩니다. 빈 부문도 안내를 표시합니다.

키보드는 Tab으로 조작할 항목을 이동합니다. 부문 탭에서는 좌우 방향키와 Home/End로 선택할 수 있습니다. 밝은 포커스 테두리를 표시하며 주요 버튼의 터치 영역은 최소 44×44px입니다. 스크롤 목록에 포커스를 주면 키보드로 목록을 스크롤할 수 있습니다.

### CSS를 이해하는 방법

- `.app-shell`: 최소 높이 `100dvh`로 실제 브라우저 영역을 사용합니다. 콘텐츠가 많으면 자연스럽게 세로로 늘어나며, 아래에는 고정 메뉴만큼 공간을 남깁니다. 전체 페이지의 스크롤을 강제로 막지 않습니다.
- `--safe-top`, `--safe-bottom`: `env(safe-area-inset-*)` 값을 받아 아이폰 안전 영역을 확보합니다. 하단 메뉴 기본 높이는 `--nav-height: 52px`입니다.
- `.header`, `.heading-row`: 로고와 제목은 유지하면서 높이와 여백을 줄입니다.
- `.route-map`: `clamp(140px, calc(100dvh - 464px - 안전영역), 420px)`로 지도 높이를 정합니다. 464px은 큰 거리 숫자·헤더·안내·보조 지표·메뉴 등에 남기는 공간입니다. 지도는 최소 140px을 유지합니다.
- `.metric-grid`: `repeat(3, minmax(0, 1fr))`로 보조 지표 3열을 만듭니다. 거리 숫자는 별도 주요 영역에 표시합니다. `min-width: 0`과 줄바꿈으로 가로 넘침을 방지합니다.
- `#ranking-view`: 화면 높이에서 헤더 44px·하단 메뉴 52px·본문 여백 18px과 안전 영역을 뺀 높이를 사용합니다. 짧은 화면에서는 최소 높이를 확보해 읽을 수 있게 합니다.
- `.ranking-dashboard`, `.ranking-scroll`: Flex로 목록에 남은 높이를 배정하고 `min-height: 0; overflow-y: auto`로 긴 목록만 스크롤합니다.

## 지도 기술 및 오류 안내

MapLibre GL JS **5.6.2**의 JS/CSS를 unpkg CDN에서 불러오고 OpenFreeMap Liberty 스타일을 사용합니다. 이 구성에는 API 키가 필요하지 않습니다. 지도 라이브러리·스타일·타일을 불러오기 위해 인터넷 연결 및 WebGL 지원 브라우저가 필요합니다.

지도 출처는 OpenFreeMap, OpenMapTiles, OpenStreetMap 기여자로 표시합니다. 마우스/손가락 드래그, 휠/두 손가락, `+ / −` 버튼으로 조작합니다. 화면 높이·너비 변경이나 기록 화면 복귀 시 지도 크기를 갱신하고 경로를 다시 맞춥니다.

CDN·지도 연결 실패 시 상태 메시지와 재시도 버튼을 표시합니다. 라이브러리는 15초, 지도는 추가 20초 후 지연 안내를 표시합니다. 연결이 복구되면 자동 재시도합니다. 오류 설명과 버튼이 늘어나면 가독성을 위해 페이지 세로 스크롤을 허용합니다. 지도 실패 중에도 랭킹과 하단 메뉴는 작동합니다.

공식 문서: https://openfreemap.org/quick_start/ , https://maplibre.org/maplibre-gl-js/docs/

## FastAPI 연동 구조

`renderTrip(trip)`에 서버 응답을 전달하면 기존 요약과 지도가 함께 갱신됩니다. `trip.path`는 GeoJSON과 같은 **[경도, 위도] 배열**이며 최소 2개 유효 좌표가 필요합니다. 수원 좌표 예시는 `[127.0166, 37.2887]`입니다. 실제 측정 데이터에는 `isDemo: false`를 넣으세요.

```js
async function loadTrip(tripId) {
  const response = await fetch(`/drive/${encodeURIComponent(tripId)}`);
  if (!response.ok) throw new Error('주행 기록을 불러오지 못했습니다.');
  renderTrip(await response.json());
}
```

실제 API 주소·인증·CORS를 확정한 뒤 `app.js`의 `getTripById(tripId)` 내부를 실제 조회로 교체합니다. URL 해석과 로딩·오류 처리는 `loadTripFromUrl()`이 담당하며, 조회 성공 시에만 지도 초기화를 수행합니다. 아래 QR 조회 절의 교체 예시를 참고하세요.

랭킹 응답은 기존 `month`, `myRank`, `podium`, `categories: [{title, entries: [{name, value}]}]` 구조로 `renderRanking(ranking)`에 전달하면 됩니다. entries는 서버에서 확정한 순위 순서로 보내세요. 본인은 명시적인 `isMe` true/false를 우선하고, 값이 없을 때 `ranking.currentUserId`와 행의 `userId`를 비교합니다. 닉네임으로는 본인을 판단하지 않습니다. 현재 currentUserId는 인증된 세션이 아니라 고정 데모 값입니다. 실제 서버 연결, 로그인, 친구 등록, GPS 측정은 구현되어 있지 않습니다.

## QR URL로 샘플 주행 기록 3개 조회하기

휴대폰 기본 카메라 등으로 **URL이 담긴 QR코드**를 읽고 브라우저를 열면 해당 주행을 표시합니다. 이 변경은 웹의 URL 조회 부분입니다. 웹 페이지 안에서 카메라로 QR을 인식하는 스캐너나 QR 이미지 생성기는 추가하지 않았습니다.

서버를 실행하고 QR코드에는 다음 URL을 넣으세요. 휴대폰과 PC는 같은 Wi-Fi여야 하며 PC의 IP가 바뀌면 QR URL도 바꿔야 합니다. 휴대폰용 QR에 `localhost`를 넣지 마세요.

| ID | 테스트용 URL | 코스 | 거리 / 시간 / 연비 |
| --- | --- | --- | --- |
| `abc123` | `http://192.168.203.63:5173/?tripId=abc123` | 기존 수원 하트 코스 | 42.3km / 1:24:10 / 12.8km/L |
| `def456` | `http://192.168.203.63:5173/?tripId=def456` | 수원 장안문 데모 코스 | 18.6km / 0:35:20 / 14.1km/L |
| `ghi789` | `http://192.168.203.63:5173/?tripId=ghi789` | 수원 팔달문 데모 코스 | 27.4km / 0:52:05 / 11.9km/L |

PC에서는 위 IP 대신 `localhost`를 사용해도 됩니다. 주소를 직접 열어서도 QR 스캔 후와 동일한 조회를 테스트할 수 있습니다. 세 경로와 모든 요약 값은 임의의 데모 데이터이며 실제 GPS 측정이나 거리 계산 결과가 아닙니다.

### URL 처리 규칙

- `tripId`가 없으면 기존 호환성을 위해 `abc123`을 표시합니다.
- `tripId`는 대소문자를 구분합니다. 현재 테스트에서는 영문·숫자·밑줄·하이픈으로 이루어진 1~64자 ID를 허용합니다. 실제 서버 ID 형식을 확정할 때 함께 조정할 수 있습니다.
- 빈 ID, 중복 ID(`?tripId=abc123&tripId=def456`), 잘못된 형식은 오류로 안내합니다.
- 형식은 맞지만 샘플에 없는 ID도 오류를 표시하며, 다른 샘플로 대체하지 않습니다. `?tripId=missing`으로 확인할 수 있습니다.
- 오류 화면은 잘못된 기록과 지도를 숨기고 기본 샘플로 돌아갈 링크를 제공합니다. 랭킹 메뉴는 계속 작동합니다.
- 하단 메뉴로 랭킹을 왕복해도 `tripId`는 URL에 남습니다. 기존 `#ranking` 링크도 유지합니다.
- 기록 날짜 옆에 조회 ID를 표시하므로 어떤 기록을 열었는지 확인할 수 있습니다.

### 코드 역할과 서버 전환 지점

QR 조회 도입 당시 변경 파일은 `data.js`, `app.js`, `index.html`, `styles.css`, `README.md`였습니다. 아래는 최초 도입 시 역할 설명입니다.

1. `data.js`: `DRIVE_RUN_TRIPS` 객체에 ID를 키로 사용해 3개 기록을 보관합니다. `abc123`은 기존 `DRIVE_RUN_MOCK.trip`을 그대로 참조하고 기존 랭킹 데이터는 바꾸지 않았습니다.
2. `app.js`: `URLSearchParams`로 ID를 읽고 `getTripById()`로 조회합니다. `renderTrip()`은 선택된 요약과 경로를 기존 UI 및 지도에 전달합니다. 요청 ID와 응답의 `tripId`가 다를 때도 오류로 처리합니다.
3. `index.html`: 조회 중/오류 메시지 영역만 추가했습니다. 시상대, 탭, 하단 메뉴는 유지합니다.
4. `styles.css`: 조회 중 다른 샘플이 잠깐 보이지 않도록 하고, 오류 안내와 복구 링크만 스타일링했습니다. 정상 화면의 기존 반응형 배치는 유지합니다.
5. `map.js`, `server.cjs`: 변경하지 않았습니다. 로컬 서버는 쿼리와 무관하게 같은 HTML을 제공하고 JavaScript가 ID를 해석합니다.

실제 연동 때는 `getTripById()` 내부를 다음과 같은 형태로 바꾸면 됩니다. **API 주소는 아직 확정되지 않았으며 아래는 예시입니다.**

```js
async function getTripById(tripId) {
  const response = await fetch(`/drive/${encodeURIComponent(tripId)}`);
  if (response.status === 404) throw new Error('해당 주행 기록을 찾을 수 없습니다.');
  if (!response.ok) throw new Error('주행 기록을 불러오지 못했습니다.');
  return response.json();
}
```

서버 응답은 기존 trip 객체와 같은 형태로 `tripId`, `courseName`, `region`, `startedAt`, `endedAt`, `distanceKm`, `durationSec`, `avgFuelEconomy`, `isDemo`, `path`를 포함하면 됩니다. `path`는 `[경도, 위도]` 배열입니다. 실제 데이터는 `isDemo: false`로 보냅니다.

실제 연동 전 함께 확정할 사항:

- 주행 완료 시 서버의 ID 발급, 저장, 중복 방지 방식
- 조회 API 주소, 응답 JSON, 오류 및 인증 방식
- QR에 담을 배포 URL, 공유 권한, 만료/접근 정책

### 데모 GPS 경로와 주행 요약의 차이

좌표 점을 순서대로 연결한 구면 거리(Haversine, 지구 반지름 6371km)를 합산했습니다. 이는 **좌표 간 선분 길이의 근사치**이며 도로 주행 거리나 실제 측정값을 검증한 결과가 아닙니다.

| ID | 기존 카드 거리 | 좌표 선분 합계 | 차이 |
| --- | --- | --- | --- |
| `abc123` | 42.3km | 약 4.859km | 약 37.441km |
| `def456` | 18.6km | 약 2.076km | 약 16.524km |
| `ghi789` | 27.4km | 약 2.256km | 약 25.144km |

표시된 거리·시간·연비와 기존 좌표는 유지했습니다. 거리를 좌표 합계로 바꾸어 실측처럼 보이게 하거나, 좌표를 늘려 거리 숫자에 맞추지 않았습니다. 시작/종료 시각의 차이는 각 durationSec(5050/2120/3125초)와 일치합니다. 시각과 연비 역시 임의 샘플이며, 실제 GPS 타임스탬프·차량 센서 기록으로 검증한 값은 아닙니다. 코스 이름도 가상 이름이며 이름과 실제 경로 형태가 일치한다는 보장은 없습니다.

화면의 안내는 **‘데모 경로 · 요약 수치는 별도 샘플’**로 표시합니다.

### 경로의 의미를 담는 필드

기존 `trip.path`의 `[경도, 위도]` 배열과 tripId는 유지하고 다음 필드를 추가했습니다. **이 필드는 현재 웹 내부의 준비 구조이며 확정된 서버 API 계약은 아닙니다.**

| 필드 | 현재 3개 샘플의 값 | 의미 |
| --- | --- | --- |
| `isDemo` | `true` | 실측 기록이 아닌 샘플 |
| `routeType` | `"demo"` | `demo`: 시각화용 임의 경로, `planned`: 계획 경로, `recorded`: 이동 기록을 나타내는 유형 |
| `pathSource` | `"synthetic"` | 임의 생성 좌표 |
| `summarySource` | `"independent_demo"` | path에서 계산하지 않은 별도 요약 샘플 |
| `roadValidated` | `false` | 실제 도로 주행 경로 검증 안 됨 |
| `userId` | `demo-user-*` | 예시 기록 소유자 ID. tripId와 별개 |

계획 경로는 실제 이동 기록이 아니라고 안내합니다. 이동 기록이라도 `isDemo`가 false로 명시되지 않으면 실측으로 표현하지 않습니다. routeType이 없거나 알 수 없는 값이면 유형과 실측 여부를 미확인으로 표시합니다. 서버가 앞으로 `recorded`를 전달하더라도 클라이언트는 그 정보를 표시할 뿐, 실제 도로 주행을 독립적으로 검증하는 기능은 아닙니다.

### 본인 식별과 고정 데모 랭킹

1. 행의 `isMe`가 boolean이면 그 값을 우선합니다. `false`도 명시적인 판단으로 취급합니다.
2. `isMe`가 없으면 비어 있지 않은 문자열 `ranking.currentUserId`와 행의 문자열 `userId`를 정확히 비교합니다.
3. 둘 다 없으면 본인으로 추정하지 않습니다. 닉네임이 ‘나’여도 본인으로 처리하지 않습니다.

샘플의 currentUserId는 `demo-user-me`이며 모든 부문과 시상대의 행에 userId와 isMe를 명시했습니다. 이름과 기존 순위·순서는 유지했습니다. 실제 인증 사용자나 친구 관계를 조회하는 기능은 없습니다.

`tripId`는 **기록 ID**, `userId`는 **사용자 ID**입니다. def456/ghi789는 샘플 소유자도 다르게 지정했지만, 해당 QR을 열어도 랭킹의 데모 사용자는 바뀌지 않습니다. QR 조회는 로그인이나 사용자 전환이 아닙니다. 랭킹 화면에 **‘고정 데모 · 로그인·친구 관계 연동 없음’**을 표시합니다.

부문별 목록은 여전히 전체 배열을 표시하며 3명으로 자르지 않습니다. 상위 3명 제한은 종합 시상대에만 적용합니다. 본인 찾기는 현재 선택한 부문의 목록만 이동합니다.

### QR와 서버 연결 범위

`?tripId=abc123`, `def456`, `ghi789`는 유지합니다. 빈 값·중복·잘못된 형식·없는 ID에서는 오류를 보이고 다른 기록으로 대체하지 않습니다. ID가 아예 없는 기존 기본 주소만 abc123으로 열립니다. 직접 접속, 새로고침, 하단 메뉴 왕복 시 쿼리 유지도 검사했습니다.

`getTripById()`는 여전히 로컬 샘플 조회 함수입니다. 이 지점을 FastAPI 요청으로 교체할 수 있도록 유지했으며 **서버 API 주소나 최종 JSON 규격은 확정하지 않았습니다**. 본문에 있는 `/drive/...`는 계속 예시입니다.

실제 서비스에서는 **서버 측 공유 권한 검사 또는 서버가 검증하는 공유 토큰** 등 접근 정책이 필요합니다. ID 문자열 형식 검사나 QR 자체는 접근 권한이 아닙니다. 토큰 전달 방식·유효기간·인증·API 오류 형식은 서버 팀과 확정해야 합니다. 현재는 공개 데모 데이터이며 로그인·친구 관계·실제 저장·권한 처리를 구현한 상태가 아닙니다.

`getTripById()` 구조와 QR의 tripId는 유지했습니다. 현재는 등록된 고양이 ID만 `DRIVE_RUN_COURSES.getById()`로 JSON을 읽고, 기존 세 ID는 원래 data.js에서 조회합니다. 알 수 없는 ID를 고양이 코스로 대체하지 않습니다.

const trip = window.DRIVE_RUN_COURSES.normalize(serverCourseJson, '부천·인천');

# 차량 QR 데이터

`?tripId={id}&d={Base64URL UTF-8 JSON}` 주소에서 `d`가 있으면 샘플 조회 없이
`qr-data.js`로 해석합니다. 현재 지원 버전은 `v: 1`이며 JSON 필드는
`id, course, region, start, end, km, sec, pl`과 선택 필드 `eff, unit`입니다.
시작/종료는 JavaScript에서 해석 가능한 날짜 문자열을 사용합니다.
`unit`은 `kwh` 또는 `l`이며 없으면 단위를 추측하지 않고 `—`로 표시합니다.
Polyline precision 5의 위도/경도를 MapLibre의 `[경도, 위도]`로 변환합니다.
빈 경로는 지도 경로 없음 안내를 사용합니다. 잘린 좌표나 범위를 벗어난 좌표는 오류입니다.

잘못된 인코딩, UTF-8, JSON, 버전, 필드, 중복 파라미터, ID 불일치는 오류 화면으로
표시하며 샘플로 대체하지 않습니다. `d`가 없으면 기존 샘플/계획 코스 조회를 유지합니다.
차량 기록에는 `VEHICLE QR` 표시와 차량 QR 좌표 안내가 붙으며 랭킹은 기존 데모입니다.

추가 검증: `node tests/check-qr.cjs` (Node 기본 모듈만 사용).
QR 파서와 결과 화면/지도 전달을 DOM 대역으로 검사합니다. 기존
`check-browser.cjs`는 새 스크립트도 로딩하며 기존 샘플·랭킹·레이아웃을 검사합니다.
실제 타일·휴대폰 터치·실물 QR 인식 검증은 별도입니다.
현재 체크아웃에는 안내받은 Android `ResultLink.kt`가 없어 전달받은 규격으로 구현했습니다.
